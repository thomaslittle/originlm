# Changelog

## Unreleased

- Add `originlm providers check|update` for provider CLI binaries (Claude Code, Codex, OpenCode, Gemini CLI, Grok, Pi, Muse Code; others report manual or unsupported with the reason). `check` reports the installed version, the latest version from the installer that owns the binary, and `current` / `behind_latest` / `manual_only` / `unknown`. `update` is explicit and CLI-only, and supports `--dry-run`. It runs only an installer proven to own the binary by its real path, one at a time per install, after re-reading ownership. Success requires the re-probed version to be current. Afterwards the provider's cached model metadata is dropped. No broker, SDK or MCP method exposes either command. See `docs/adapters/provider-updates.md`.

## 0.1.0-alpha.28 - 2026-11-11

- Expose the `originlm` helper entry point as a library: `originlm_cli::run()` and `run_from()`. A Rust host can now build the helper from the published crate with its own lockfile and toolchain, so no prebuilt archive, pinned checksum or out-of-band compile is needed. No behavior, argument or protocol change.

## 0.1.0-alpha.27 - 2026-11-09

- Add `originlm image` to the helper, so npm, PyPI and crates.io installs can run `generate_image`. `--definition` prints the tool schema without contacting a provider; generation requires `--allow-paid` and uses `ORIGINLM_IMAGE_ROUTE` or the installed Codex login. Publish the new `originlm-images` crate as part of a 15-crate closure.

- Default desktop image generation to the installed Codex subscription, independently of the conversation model; keep explicit API routes optional. Add compact icon-only image file actions and native desktop generation evidence. Fix Windows subprocess stdin EOF handling.

- Add host-owned `generate_image` through `originlm-images` and `originlm_kit::images`: configurable OpenAI Images 2.6 and Google Nano Banana 2.1/Pro routes (including OpenRouter), reference edits, exact canvas PNG assets, typed errors and authenticated host MCP. Desktop native host-tool turns can show trusted generated files inline after explicit paid-route approval. Direct HTTP chat tool loops and Crntly placement remain follow-ups.
